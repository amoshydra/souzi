# UI localisation

Souzi ships three interface languages:

| Locale | Name | File |
| --- | --- | --- |
| `en` | English | `src/i18n/locales/en.ts` |
| `zh-Hans` | 简体中文 | `src/i18n/locales/zh-Hans.ts` |
| `zh-Hant` | 繁體中文 | `src/i18n/locales/zh-Hant.ts` |

The UI language is separate from dictionary content and text-to-speech. A
Chinese interface still searches English and still speaks English words with an
English voice.

## How it works

- `i18next` + `react-i18next`, with every catalog bundled in the app. There is
  no network request for translations and no translation backend.
- `src/i18n/index.ts` detects the system language, stores the preference in
  `souzi-locale`, updates `<html lang>` / `dir`, and exposes
  `useLocalePreference()`.
- The English catalog is the source of truth. The other catalogs are typed
  against its shape with `satisfies DeepString<EnglishCatalog>`, so a missing
  key fails `pnpm build`.
- The Settings page and the first-run setup page both include a language
  selector. The default is “System”.

## Adding or changing a string

1. Add the English string to `src/i18n/locales/en.ts` first.
2. Add the same key to `zh-Hans.ts` and `zh-Hant.ts`.
3. Run `pnpm test`. The catalog test checks:
   - all three catalogs have the same keys,
   - interpolation placeholders match,
   - plural groups have `_one` and `_other`.
4. Run `pnpm build` (or `pnpm exec tsc --noEmit`).

Conventions:

- Keys are grouped by screen/feature (`search`, `entry`, `packs`, `setup`,
  `import`, `install`, `about`, `settings`, `saved`, `errors`, `units`, `a11y`).
- One complete sentence per key. Do not concatenate translated fragments.
- Interpolate with `{{name}}`; let React escape the result.
- Use `_one` / `_other` for plurals and pass `count`:
  `t("search.resultCount", { count })`.
- Use `<Trans>` when a sentence contains a link or inline markup that must keep
  a `lang` attribute (for example “Also written <trad>詞</trad>”).
- Do not translate product names, data-source names, license names, or URLs:
  Souzi, 搜字, HSK, CC-CEDICT, ECDICT, Tatoeba, WordNet, Wi-Fi, Android, GitHub.
- Chinese copy uses full-width punctuation and the “你” register. Prefer short,
  direct sentences over literal translations.

## Adding a locale

1. Add the locale code to `SUPPORTED_LOCALES` in `src/i18n/types.ts`.
2. Add its endonym to `LOCALE_ENDONYMS`.
3. Create `src/i18n/locales/<locale>.ts` with
   `satisfies DeepString<EnglishCatalog>`.
4. Import it lazily through the `localeLoaders` map in `src/i18n/index.ts`.
   Do not add it to the static `resources`; English stays there as the fallback.
5. Extend `resolveLocale()` in `src/i18n/index.ts` with the correct language-tag
   mapping. Use `nonExplicitSupportedLngs: false` and `load: "currentOnly"`:
   script subtags such as `zh-Hans` must match exactly.
6. Add a plural test for the locale in `src/test/i18n.test.ts`.
7. Test the interface at 320px and 390px width; text length changes with every
   language.

## Lazy loading and code splitting

- English is in the main chunk because it is the fallback. `zh-Hans` and
  `zh-Hant` are separate dynamic-import chunks; only the active locale is
  evaluated at startup.
- `main.tsx` awaits `initI18n()` before the first React render. A language-neutral
  spinner in `index.html` covers that short load, so a Chinese user never sees
  an English flash.
- `ensureLocale()` caches loaded catalogs and de-duplicates concurrent loads.
  Switching language in Settings/Setup loads that locale's chunk on demand and
  disables the selector while it loads. The PWA precaches the small chunks so
  offline switching still works after installation.
- Secondary routes (`EntryView`, `SavedView`, `SettingsView`, `DownloadsView`,
  `ImportView`, `AboutView`) are `React.lazy` chunks with a translated
  `RouteFallback`. Saved/Settings are warmed on nav hover/focus. The initial
  app chunk contains the shell, Search, and Setup.
- Vendor code is split into `react`, `i18n`, `icons`, and `vendor` chunks so no
  single production chunk crosses the 500 KB warning threshold.
- To add a locale, add a loader to `localeLoaders` in `src/i18n/index.ts`; Vite
  then emits a separate chunk automatically.

## Language tags

The interface language is set on `<html>`. Dictionary content is tagged
separately: `lang="zh-Hans"` / `lang="zh-Hant"` for known script fields,
`lang="zh"` for Chinese data whose script is not guaranteed, `lang="zh-Latn"`
for pinyin, and `lang="en"` for English definitions and examples. Do not tag
data with the interface language; a Chinese UI can display English content.

## Language switcher and fallback

- The select always shows the **actual resolved UI language**, not the stored
  preference. The separate **Auto** toggle represents “follow system language”.
- The fallback locale is **English**. It is the always-bundled source catalog
  and i18next’s `fallbackLng`. Unsupported system languages and failed locale
  chunks resolve to English; the switcher shows English and, for a failed
  chunk, an explanatory status message.
- Script wins over region: `zh-Hans-HK` is Simplified, `zh-Hant-CN` is
  Traditional. Without a script, `TW`/`HK`/`MO` use Traditional; other `zh`
  tags use Simplified. See `resolveLocale()` and its table tests.

## Errors

Do not store English error strings in React state, hooks, workers, or native
bridge payloads. Throw `AppError` from `src/i18n/errors.ts` with a translation
key:

```ts
throw new AppError("errors.network");
throw new AppError("errors.notCedict", { count: parsed.length });
```

Render it with `translateError(t, error)`. The import worker sends error codes
over `postMessage`; it never sends translated text.

## Formatting

`src/lib/format.ts` uses the active locale for `Intl.NumberFormat` and
`Intl.DateTimeFormat`. Dictionary counts, dates, and storage sizes must go
through those helpers rather than `toLocaleString()` with no locale.

## Verification

```bash
pnpm test          # catalog parity, placeholders, plurals, locale detection
pnpm i18n:check    # the i18n tests only
pnpm build         # typed catalogs + production build
pnpm dev           # manual check
```

The UI is reviewed with keyboard-only navigation, TalkBack on Android, and a
desktop screen reader. See `docs/i18n-accessibility-plan.md` for the
accessibility checklist and glossary.
